# Подключение графики к Sportzal

## Минимальный перенос

1. Скопировать содержимое android/res/ в app/src/main/res/. Все ресурсы имеют префикс sz_ для снижения риска конфликтов имён.
2. Не копировать masters, previews, svg или дубли PNG в APK. Для приложения достаточно папки android/res/.
3. Сопоставить реальные equipment_id и exercise_id с ресурсами из manifest.json. Имена row, leg_press и т.п. — типы графики, а не идентификаторы оборудования пользователя.
4. Картинки показывать с ContentScale.Fit. Не обрезать ContentScale.Crop: у схем важны ручки, рычаги и упоры.
5. В светлой теме подходят исходные цвета; иконки перекрашиваются штатным tint. Изображения техники не перекрашивать как монохромные иконки.
6. Все названия, вес, повторы, номера настроек и подписи оставлять живым текстом. Минимальная область касания кнопок — 48 dp, независимо от размера иконки 24 dp.

## Примеры имён

- R.drawable.sz_eq_row — большая схема горизонтальной тяги.
- R.drawable.sz_thumb_row — миниатюра каталога.
- R.drawable.sz_tech_row_00 / sz_tech_row_01 — отдельные положения.
- R.drawable.sz_tech_row_pair — готовая пара в одном изображении.
- R.drawable.sz_ic_timer — векторная иконка времени.
- R.color.sz_primary — основной синий.

В Compose картинки и VectorDrawable можно загрузить через painterResource. Никакой сетевой загрузки или стороннего image-loader для этих локальных ресурсов не требуется. Полоса с парой подходит для компактной панели техники, отдельные кадры — для увеличенного просмотра.

## Связь с текущим приложением

manifest.json — описание данного пакета графики. Это не sportzal.program и не ai_snapshot; отправлять его в существующий импорт тренировок не нужно. В текущей схеме v1 отсутствуют поля media. Подключение этих локальных ресурсов возможно отдельным отображением type → drawable; доставка пользовательских media-пакетов требует самостоятельного контракта.

На экране тренажёра схема оборудования показывается в режиме просмотра. Изменение персональной настройки открывается отдельным действием. В упражнении используются та же схема и кадры конкретного движения. Отсутствие схемы не блокирует ввод фактического подхода: остаётся текстовая инструкция.

## Дальнейшее расширение

При замене типового изображения на конкретную модель сохранять роли equipment / technique_keyframe, поля и правила Fit. Не вставлять новую схему поверх прежней только по похожему названию: идентичность оборудования определяется программой и каталогом. Номера точек регулировки назначаются по конкретному рисунку; универсальные координаты для разных моделей здесь не выдумывались.
