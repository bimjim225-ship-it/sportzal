# Sportzal: согласованный рабочий сценарий

Основание: аудит и восемь экранов от 25 октября, графический пакет v1, указание владельца от 26 октября внедрить обсуждённый план. Существующая основа Android/Kotlin/Compose/Room сохраняется. Внешний ИИ получает JSON и возвращает новую программу; сетевой ИИ в приложение не добавляется.

## Результат

Сегодня → просмотр плана (без создания попытки) → явное начало → обзор активного занятия → одно выбранное упражнение → запись факта → обзор/следующее упражнение → итог → системная отправка отчёта → предпросмотр и принятие нового плана.

Каталог открывает просмотр тренажёра; изменение настроек — отдельное действие. Поиск локальный с очисткой. Фото остаётся необязательным исходником, основное изображение — схема. Выбор одной из пяти типовых схем явный, без угадывания модели по названию. Техника связывается с упражнением отдельно; неизвестному упражнению нельзя молча назначать чужую технику. Схемы и две ключевые позы — иллюстрации; переменные назначения выводятся живым текстом.

## Ограничения

- minSdk 26, compileSdk/targetSdk 35; существующие версии зависимостей.
- Внешние JSON v1, неизменность снимка плана, история фактов и алгоритм prefill сохраняются.
- Все изменения Room сопровождаются настоящими экспортированными схемами и миграционными тестами; destructive migration запрещена.
- Вес/повторы/явный ответ RIR переживают восстановление. «Не оценил» отличается от отсутствия ответа.
- Back не завершает занятие. Выбор упражнения/настройки и draft сохраняются; при ошибке записи уход не объявляется безопасным.
- Rotation доступен из обзора; выбранная карточка не заменяется под пальцем, после записи переход только по явному действию.
- Плановая пауза и интервал «С записи» различимы; чистый отдых не измеряется.
- Нет технических ID в основном интерфейсе, фиктивной оценки эффективности, автоматической прогрессии и объявления доставки файла.
- Светлая палитра DESIGN.md, Roboto, крупные числа, нативные контролы от 48 dp, русский текст и числа с запятой.

## Архитектура и принятые решения

Сохраняем Room-репозиторий и WorkoutViewModel как владельцев фактов. Новые вычисления прогресса отделяем от Compose. Каталог медиа — локальное сопоставление equipment_id/exercise_id с ключом встроенного ассета; JSON программы не расширяется. Общие компоненты заголовка, статуса, кнопки и изображения используются всеми экранами. MainActivity остаётся Android-хостом, повторная логика обмена выделяется.

Переписывание на web/native-cross-platform отвергнуто: требует миграции проверенного хранения. Косметическая замена цветов отвергнута: не исправляет основной сценарий. Выбран перенос согласованного UX на текущую нативную основу по проверяемым коммитам.

## Дальнейшее развитие медиа

Генерация по реальному фото, проверка техники и установка произвольных пакетов требуют отдельного формата/импорта медиа. В этой доработке используются подготовленные встроенные схемы с явным выбором и текстовым fallback. Это согласованная точка расширения, а не фиктивная работающая генерация.

## Проверка

Unit: восстановление трёх состояний RIR, счётчики plan/fact/extra/skip, выбор медиаматериала, импорт и навигация. Room: миграции и сохранение каталога/фактов. Compose: обзор, выбор упражнения, Save видимого ввода, возврат и продолжение, поиск/очистка, предпросмотр импорта. Сборка APK, lint, документация, ресурсная проверка. Скриншоты и проверка на устройстве — только при доступном Android runtime; отсутствие указывается явно.
