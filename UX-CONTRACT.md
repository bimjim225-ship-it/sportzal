# Sportzal UX Contract

## Product context

- **Audience:** один владелец Android-смартфона.
- **Primary jobs:** увидеть план; быстро записать подход; увидеть время с предыдущего подхода; продолжить тренировку после сворачивания/закрытия; отправить один JSON после тренировки.
- **Target market:** персональный продукт, без требований массового рынка.
- **Active locale:** `ru-RU`.
- **Language/content register:** короткий утилитарный русский; `RIR` допустим с подсказкой «сколько повторов осталось в запасе»; вес показывается в `кг`.
- **Timezone/calendar policy:** локальное время устройства; `planned_date` трактуется как локальная календарная дата без timezone-конвертации.
- **Accessibility target:** WCAG 2.2 AA как ориентир плюс Android accessibility semantics; touch-targets не меньше 48 dp.

## Navigation

### Inactive state

Primary destinations:

1. `Сегодня`;
2. `История`;
3. `Тренажёры`.

### Active workout state

После начала тренировки открывается отдельный full-screen workout flow. Bottom navigation скрыта.

Back:

- не завершает тренировку;
- возвращает на `Сегодня` без подтверждения для уже сохранённых данных; изменённый черновик сохраняется локально отдельно от подхода, ошибка сохранения черновика требует выбора «Остаться» / «Уйти без изменений»;
- сама тренировка остаётся активной и полностью сохранённой.

На `Сегодня` при наличии активной тренировки главное действие — `Продолжить тренировку`.

## Home / Сегодня

Порядок приоритетов:

1. активная незавершённая тренировка;
2. самая ранняя ещё не начатая тренировка активной программы (planned_date, затем порядок массива), включая прошедшую дату;
3. список остальных тренировок для ручного выбора;
4. если программа исчерпана — «План выполнен» и `Импортировать программу`; если программы нет — пустое состояние с тем же действием.

Дата не запрещает запуск и не переключает A/B автоматически. Для каждого `(program_id, workout_instance_id)` сохраняется факт начатой попытки между версиями: ИИ сохраняет ID при переносе даты, создаёт новый для нового занятия. Одновременно существует максимум одна активная тренировка; повторный тап запуска её не дублирует.

Экран не делает вывод, надо ли пользователю тренироваться сегодня. Он только отображает состояние программы.

## Start workout

`Начать тренировку`:

- создаёт локальный `workout_id`;
- фиксирует ссылку на `program_id`, `program_version`, `workout_instance_id`, `template_id`;
- копирует необходимый план в immutable snapshot тренировки;
- записывает `started_at`;
- открывает первый блок.

После создания активной тренировки последующий импорт программы не изменяет уже начатую тренировку.

## Workout screen

### Общая структура

```text
← Тренировка A                       31:42

Блок 1 · грудь / спина
[ карточки активного блока ]

Блок 2 · ноги
[ свернутый preview ]

...

Завершить тренировку
```

Header показывает полное время с запуска, включая перерывы и фон. Сохранённые отметки времени и монотонные часы определены в docs/data-contracts.md; background-job не нужен.

### Straight block

- содержит ровно одно упражнение;
- карточка остаётся наверху до выполнения всех запланированных подходов или явного завершения/пропуска;
- таймер показывает время с последней записи этого экземпляра упражнения; до первой записи — «Ещё не записывали».

### Rotation block

- содержит 2–N упражнений;
- до первого подхода упражнения без timestamps сохраняют `planned_order` и располагаются выше уже начатых упражнений;
- после того как у упражнения появился `completed_at`, его динамический ключ — elapsed time с последнего подхода;
- среди начатых упражнений большее elapsed time располагается выше;
- пользователь может нажать любую карточку независимо от позиции;
- никакого текста `пора`, `готов`, `слишком рано` приложение не генерирует;
- плановый отдых показывается как справочный параметр рядом с планом.

Сортировка пересчитывается после записи/удаления подхода и при возвращении в foreground. Во время ввода, касания, прокрутки, открытой клавиатуры/меню или фокуса TalkBack карточки не переставляются; перестановка откладывается до окончания взаимодействия. Черновик и focus привязаны к exercise_instance_id, не к позиции. Обновление цифр каждую секунду не вызывает пересортировку и озвучивание. Якорь прокрутки сохраняется.

## Exercise card

Карточка показывает:

- название;
- локальное фото, если есть;
- setup hint;
- выполненные / запланированные рабочие подходы; разминка и пропуски отмечены отдельно;
- текущий план;
- timer;
- список уже выполненных set rows;
- поля следующего подхода;
- RIR selector только при необходимости;
- `Записать подход`;
- `⋯`.

### Prefill

Следующий подход получает значения по единому правилу из docs/data-contracts.md (§ Prefill): текущий план имеет приоритет при изменении цели, типа подхода или оборудования. Предыдущий факт переносится только между одинаковыми плановыми целями на том же оборудовании и с тем же способом учёта нагрузки. Для первого подхода повторения = reps_min (подставленное значение, не рекомендация). RIR никогда не копируется ни из плана, ни из прошлого факта.

Пример: разминка 20 кг → рабочий 40 кг: поле показывает 40. Затем рабочий 40 кг с тем же планом → можно сохранить введённые пользователем 42,5 кг. При новой плановой цели 35 кг поле показывает 35.

Prefill — удобство ввода, а не рекомендация.

## Save set

После `Записать подход` приложение атомарно:

1. валидирует числовые поля: конечный вес >= 0, целые reps >= 0; RIR выбран либо явно «Не оценил», если его запросил план;
2. сохраняет set result в Room;
3. сохраняет время исходного нажатия completed_at, set_result_id и sequence_no; retry использует те же ID и timestamp, уникальность планового слота защищена на уровне БД;
4. удаляет только успешно сохранённый черновик и создаёт prefill для следующего свободного планового слота;
5. обновляет `n / total`;
6. запускает отображаемый timer через разницу timestamps;
7. в rotation-блоке пересортировывает карточки, когда завершилось взаимодействие. Двойное касание не должно попасть на уже обновлённую кнопку следующего подхода: новое действие доступно только после отпускания всех касаний, а обработчик связан с исходным слотом.

Не показывать success-dialog. Допустим короткий haptic feedback и тихая визуальная фиксация сохранённой строки.

Если запись в Room не удалась, карточка сохраняет введённые значения и показывает локальную ошибку с действием `Повторить`.

## Edit set

Тап по сохранённой строке открывает редактирование.

При изменении:

- `completed_at` не меняется;
- записывается/обновляется `edited_at`;
- timer следующего подхода продолжает опираться на исходный `completed_at`;
- можно изменить weight, reps, RIR, фактическое оборудование и deviation flags.

Удаление ошибочной записи — действие с app-owned confirmation, доступное и в истории. В одной транзакции удаляется факт, пересчитываются счётчики и latest-set timer, плановый слот становится свободным, номера оставшихся фактов не перенумеровываются. Завершённая тренировка после потери планового факта становится ended_early, но автоматически не открывается. Повторный экспорт показывает актуальное исправленное состояние. Дополнительный подход через ⋯ получает planned_set_no = null и не закрывает плановый слот.

## RIR

Показывать только если planned exercise требует его для текущего рабочего подхода.

- `none`: selector отсутствует;
- `last_work_set`: selector только на последнем planned work set;
- `all_work_sets`: selector на каждом planned work set;
- warmup set не требует RIR, если это отдельно не указано в данных будущей версии схемы.

`4+` экспортируется как `rir: 4`, где контракт определяет 4 как capped bucket `>=4`. Начальное значение пустое. «Не оценил» сохраняет null, без штрафа/оценки. Для раннего окончания с last_work_set можно дополнить RIR последней фактической строки, но завершение не блокируется. Сбор последнего RIR не позволяет ИИ утверждать RIR всех предыдущих подходов.

## Deviations / ⋯

В обычном потоке пользователь ничего не отмечает.

Доступные коды MVP:

- `range_shortened`;
- `technique_changed`;
- `discomfort`;
- `setup_changed`;
- `equipment_changed`;
- `other`.

При `equipment_changed` можно выбрать оборудование из каталога либо добавить короткое название нового оборудования с локальным ID. Поле веса очищается, так как 40 кг на другом тренажёре не обязаны быть сопоставимы. Пользователь задаёт способ учёта нагрузки при его отличии. Новое оборудование и настройка сохраняются для следующих подходов данного экземпляра, прошлые факты неизменны.

`setup_changed` открывает текст конкретной новой настройки («Сиденье 5»), а не только флаг. `Заменить упражнение` позволяет выбрать упражнение из программы либо ввести название с новым локальным ID; исходный план остаётся, фактические ID/название фиксируются с подходом. Приложение не объявляет замену эквивалентной и не подбирает нагрузку. RIR, боль и техника не переносятся автоматически в следующий подход.

Свободный комментарий необязателен и короткий.

## Skip / incomplete

Через `⋯` можно пропустить очередной подход или все оставшиеся подходы упражнения. Выполненные ранее подходы сохраняются. Каждый пропущенный слот записывается в skipped_sets с причиной и временем; «Вернуть в план» удаляет отметку пропуска в активной тренировке.

Причина необязательна; доступные quick reasons:

- `equipment_busy`;
- `time_limit`;
- `fatigue`;
- `discomfort`;
- `other`.

Невыполненные planned sets не удаляются из плана. Snapshot позволяет ИИ видеть разницу plan/fact.

## Block completion

Когда все упражнения блока выполнены или явно пропущены:

- блок сворачивается;
- появляется следующее плановое содержимое;
- приложение не показывает оценку качества блока.

Приложение не перемешивает блоки автоматически. Пользователь может раскрыть preview и нажать «Перейти к блоку», затем вернуться тем же способом. Незаконченный блок остаётся в плане, черновики сохраняются, переключение не создаёт пропусков. При закрытии блока по фактам/пропускам предлагается первый ещё незакрытый блок в плановом порядке, включая ранее отложенный. sequence_no фактов сохраняет реальный порядок. Переход назад к законченному блоку позволяет просмотреть/исправить запись.

## Finish workout

`Завершить тренировку`:

- если остались planned sets, показывает app-owned confirmation `Завершить с невыполненными подходами?`;
- после подтверждения пишет finished_at; completed означает, что все плановые подходы выполнены, иначе ended_early (включая явно пропущенные);
- невыполненные подходы без явной причины остаются незаписанными, приложение не придумывает причину;
- после последнего подхода остаётся видимое действие «Завершить тренировку»; автозавершения нет;
- все фактические данные уже находятся в Room, поэтому завершение не является «сохранением всей тренировки»;
- открывает Finish screen.

### Finish screen

Показывает только факты:

- длительность;
- число выполненных рабочих подходов;
- число упражнений с фактическими подходами;
- наличие невыполненных planned sets.

Не показывает «эффективность», «прогресс», калории или motivational score.

Primary action:

> **Отправить JSON**

Secondary:

> **Закрыть**

## Share JSON

`Отправить JSON`:

1. формирует snapshot по `docs/data-contracts.md`;
2. сохраняет временный `.json` в app cache;
3. публикует файл через Android `FileProvider`/content URI;
4. вызывает `ACTION_SEND` с MIME `application/json` и read permission;
5. Android показывает системный Share Sheet;
6. Sportzal не хранит выбранный канал и не считает открытие chooser подтверждением доставки.

Filename:

```text
sportzal-ai-YYYY-MM-DD-HHmmss-<export-id>.json
```

Та же кнопка «Отправить JSON» доступна на «Сегодня», Finish и в деталях истории. До первой тренировки экспорт передаёт каталог и программу без результатов — для первичного обсуждения с ИИ. Из истории экспорт гарантированно включает выбранную тренировку как focus_workout_id. Состояния: подготовка (без блокирования потока UI), ошибка с повтором, открытый chooser; отмена не считается отправкой. Рядом вторичное «Сохранить файл» через системный выбор места — если нужного приложения нет в списке. Snapshot содержит последние 24 законченные тренировки и явно показывает охват; восстановление базы не обещается.

## Import program

Два entry point:

1. `Импортировать программу` → Android system document picker;
2. compatible JSON, переданный Android через `Open with Sportzal`.

Import flow:

1. прочитать файл;
2. проверить JSON syntax;
3. проверить `schema == sportzal.program`;
4. проверить `schema_version`;
5. проверить структурные инварианты по schema/контракту;
6. показать короткий preview: версия программы, ближайшие даты, число тренировок/упражнений;
7. `Импортировать`;
8. в одной транзакции сохранить программу и `equipment_upserts`;
9. сделать новую программу активной для будущих тренировок.

Приложение не оценивает качество программы.

### Import errors

Показывать конкретно:

- `Файл не является JSON`;
- `Неподдерживаемая схема`;
- `Версия формата не поддерживается`;
- `В первой тренировке отсутствуют блоки` (технический путь доступен в раскрываемых подробностях для исправления ИИ);
- `Оборудование из программы не найдено` с названием/ID в подробностях.

Повтор того же ID/версии и содержимого — «Уже импортировано», без повторного upsert и смены активной версии. Иное содержимое под тем же ID/версией отклоняется: ИИ должен повысить program_version. Возврат к старой версии возможен только отдельным явным выбором пользователя на preview, без изменения истории.

Введённые/существующие данные не изменяются при неуспешном импорте.

## Equipment

Equipment list показывает:

- название;
- локальное фото, если привязано;
- setup hint;
- необязательные заметки.

Из приложения можно добавить тренажёр по названию, уточнить setup hint и привязать/сменить локальную фотографию. Фото копируется из системного picker в app-private storage, временный URI не считается постоянным фото. Ошибка фото оставляет рабочую текстовую карточку. В notes каталога ИИ может хранить доступные нагрузки; структурный available_weights_kg поддерживает неравномерные ступени, не ограничивая запись реального веса. Исторические настройки не меняются вслед за каталогом. Краткая заметка ко всей тренировке доступна через ⋯ и на Finish, без обязательной анкеты.

## Async and resilience

- **Mutation model:** локальные записи pessimistic/transactional; UI считает set сохранённым только после успешной записи Room.
- **Auto-save:** каждый set сохраняется сразу; active workout восстанавливается после process death.
- **Offline:** полная функциональность без сети.
- **Network:** отсутствует как продуктовая зависимость MVP.
- **Timer resilience:** монотонное время в пределах одной загрузки устройства; после перезагрузки wall-clock fallback с пометкой приблизительности. См. docs/data-contracts.md.
- **Duplicate submit:** кнопка `Записать подход` блокируется на время локальной транзакции.
- **Program import:** атомарная транзакция; partial import запрещён.
- **Share failure:** snapshot остаётся регенерируемым из Room; пользователь может повторить `Отправить JSON`.

## Validation

- Kotlin serialization/deserialization + отдельные structural invariants;
- JSON Schema в `docs/schemas` является нормативной документацией интерфейса, но runtime validator может быть компактнее при эквивалентном результате;
- пользовательские числовые поля валидируются непосредственно перед локальным save;
- ошибки не очищают введённые значения;
- программа не импортируется частично.

## Accessibility and touch

- минимум 48 dp для touch targets;
- content descriptions для icon-only controls;
- таймер не зависит только от цвета;
- dynamic sorting не должна похищать accessibility focus;
- при включённом TalkBack после сохранения set объявляется факт сохранения, но не весь пересортированный список;
- системная клавиатура должна закрываться одним действием и не перекрывать primary save control.
