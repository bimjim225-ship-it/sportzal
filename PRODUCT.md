# Sportzal — Product Contract

## 1. Назначение

Sportzal — персональный Android-инструмент для одного конкретного пользователя, который тренируется примерно два раза в неделю и получает программу тренировок от внешнего ИИ.

Продукт оптимизируется не под массовый рынок и не под универсальность, а под один сценарий: во время тренировки нужно за 3–5 секунд зафиксировать подход и снова убрать телефон.

## 2. Основной цикл

1. Пользователь передаёт ИИ сведения о доступном оборудовании и историю тренировок.
2. ИИ создаёт `sportzal_program.json`.
3. Пользователь открывает JSON на Android и импортирует его в Sportzal.
4. Sportzal показывает запланированную тренировку и её блоки.
5. После каждого подхода пользователь быстро фиксирует фактический вес, повторения и, если предусмотрено программой, RIR.
6. Sportzal сохраняет время нажатия «Записать подход»; физическое начало/окончание подхода не измеряется.
7. Таймеры на экране показывают, сколько прошло с последнего подхода каждого упражнения.
8. После тренировки Sportzal одной кнопкой создаёт `sportzal_ai_snapshot.json` и открывает стандартное Android-меню «Поделиться».
9. Пользователь отправляет файл себе в Telegram, почту, Drive или другой удобный канал и открывает его на компьютере в чате с ИИ.
10. ИИ анализирует историю и возвращает следующую версию программы.

## 3. Жёсткая граница ответственности

### Sportzal делает

- отображает программу без самостоятельной тренировочной интерпретации;
- хранит локальный каталог оборудования;
- хранит программы и их версии;
- создаёт и восстанавливает активную тренировку;
- фиксирует фактические подходы;
- фиксирует timestamps;
- показывает таймеры как арифметику времени от timestamps;
- сортирует упражнения активного rotation-блока по времени с последнего подхода;
- сохраняет редкие отклонения, если пользователь их указал;
- хранит историю локально;
- импортирует программу из JSON;
- экспортирует AI-ready JSON;
- вызывает системный Android Share Sheet.

### Sportzal не делает

- не решает, вырос ли пользователь;
- не меняет веса, повторы, RIR, объём или отдых;
- не строит тренировочную прогрессию;
- не оценивает усталость;
- не рекомендует deload;
- не оценивает достаточность отдыха;
- не рассчитывает «эффективность» тренировки;
- не выдаёт советы по технике;
- не генерирует программу;
- не вызывает LLM/API;
- не требует аккаунта;
- не использует облачную синхронизацию в MVP;
- не требует веб-клиента;
- не требует интернет-соединения.

Формула границы:

```text
DISPLAY → INPUT → TIMESTAMP → STORE → EXPORT
```

Внешний ИИ выполняет:

```text
ANALYZE → DECIDE → GENERATE NEXT PROGRAM
```

## 4. Принцип простоты

Главный KPI интерфейса:

> Обычный рабочий подход должен быть записан за 3–5 секунд и минимальное количество касаний.

Следствия:

- никаких обязательных анкет перед тренировкой;
- никаких графиков в MVP;
- никаких ежедневных оценок сна/готовности;
- никаких обязательных комментариев;
- никаких подтверждений настройки тренажёра на каждом подходе;
- значения следующего подхода предварительно заполняются из плана или предыдущего фактического подхода;
- редкие события спрятаны за вторичным действием `⋯`.

## 5. Тренировочная модель

Программа состоит из тренировок, тренировки — из блоков.

Поддерживаются два режима блока:

### `straight`

Один тренажёр/упражнение выполняется подход за подходом. Между подходами приложение показывает время от предыдущего подхода этого упражнения.

### `rotation`

В блоке находится 2–N упражнений. Пользователь чередует их, пока не выполнит заданное число подходов каждого упражнения.

Внутри активного rotation-блока:

- все незавершённые упражнения доступны в одной прокручиваемой ленте;
- упражнения, у которых ещё не было подхода, идут по плановому порядку;
- после первого круга начатые упражнения сортируются по убыванию времени с последнего подхода;
- сортировка является только представлением факта, а не рекомендацией;
- пользователь может выбрать любую карточку вручную.

Порядок блоков задаётся программой и сохраняется как основная структура тренировки. Если тренажёр занят, пользователь может вручную открыть другой блок и затем вернуться; приложение ничего не перепланирует и сохраняет фактический порядок записей. Локальные пары — основной сценарий, большой круг допустим, но приложение не считает любую пару антагонистами.

## 6. План против факта

Sportzal хранит оба слоя отдельно.

### План

Может содержать:

- упражнение;
- оборудование;
- настройки оборудования для напоминания;
- число и тип подходов;
- целевой вес;
- диапазон повторений;
- целевой RIR;
- плановый отдых;
- политику сбора RIR;
- заметку ИИ.

### Факт

Содержит только наблюдаемые события:

- фактическое оборудование для каждого подхода;
- фактический вес;
- фактические повторения;
- фактический RIR, если введён;
- точный `completed_at`;
- `edited_at`, если запись была исправлена позже;
- код отклонения, если пользователь его указал.

Из времени записей вычисляется только интервал между сохранениями подходов. Он включает выполнение следующего подхода и задержку ввода, а в rotation — также другие упражнения. Чистый отдых не измеряется. Плановая пауза остаётся отдельной инструкцией ИИ.

## 7. RIR без лишнего трения

RIR полезен для анализа, но не должен превращать тренировку в анкету.

Программа определяет `rir_capture`:

- `none` — RIR не спрашивается;
- `last_work_set` — RIR фиксируется только на последнем рабочем подходе упражнения;
- `all_work_sets` — RIR фиксируется на каждом рабочем подходе.

В UI используется шкала `0 / 1 / 2 / 3 / 4+`. Значение `4` в экспортируемых данных означает `4 или больше`.

## 8. Редкие отклонения

Отсутствие отметки означает «отклонение не сообщено», а не подтверждённое отсутствие боли или идеальную технику. Пользователь не подтверждает это каждый раз.

Через `⋯` можно отметить:

- сокращённую амплитуду;
- заметное изменение техники;
- дискомфорт/боль;
- изменение настройки тренажёра;
- замену оборудования;
- пропуск упражнения;
- произвольный короткий комментарий.

Эти данные сохраняются как факт, но приложение их не интерпретирует.

## 9. Расписание

Sportzal не интегрируется с Android Calendar в MVP.

Входная программа содержит конкретные `planned_date` для ближайших тренировок и последовательность шаблонов (`A`, `B` и т. п.). Экран «Сегодня» показывает:

- активную незавершённую тренировку, если она существует;
- самую раннюю ещё не начатую тренировку программы, включая прошедшую дату;
- остальные тренировки доступны для ручного выбора. Завершённая или досрочно законченная попытка не предлагается автоматически повторно.

Пропуск даты не уничтожает тренировку и не заставляет приложение автоматически перескакивать на другой шаблон.

## 10. Локальность и внешняя копия

MVP — полностью локальный.

- основная база: Room;
- фотографии оборудования: app-private storage;
- сеть не требуется;
- Firebase отсутствует;
- авторизация отсутствует.

`Sportzal AI Snapshot` — внешняя копия включённой части истории для анализа. Это не полный backup: по умолчанию включены 24 законченные тренировки, фотографии отсутствуют, восстановления базы из snapshot в MVP нет. Удаление приложения/данных или потеря телефона может лишить локальной истории. Отправка файла не равна подтверждённой доставке. Облако не требуется для согласованного сценария обмена.

Фотографии оборудования в AI snapshot не встраиваются. Они считаются необязательным локальным удобством, а не критическими данными истории.

## 11. Импорт и обмен файлами

### Из ИИ в приложение

MVP поддерживает:

- системный выбор JSON-файла;
- открытие совместимого JSON через Android `Open with / Открыть с помощью Sportzal`, когда Android предоставляет файл приложению.

Один `sportzal_program.json` может одновременно содержать новые/обновлённые записи оборудования и новую программу. Пользователь не должен вручную синхронизировать два файла.

### Из приложения к ИИ

После завершения тренировки primary action:

> **Отправить JSON**

Sportzal создаёт один `sportzal_ai_snapshot.json` и открывает Android Share Sheet. Пользователь сам выбирает Telegram, почту, Drive и т. п.

## 12. История для ИИ

AI snapshot должен содержать достаточно сырых данных, чтобы ИИ мог пересчитать интервалы между записями и анализировать динамику с учётом ограничений измерения.

Для MVP экспортируется:

- сведения о схеме;
- активная программа;
- каталог оборудования;
- все сохранённые версии программ, на которые ссылается экспортируемая история;
- последние 24 законченные тренировки (completed/ended_early) по started_at или все, если их меньше;
- последняя завершённая тренировка всегда включается;
- единственная активная тренировка включается отдельно без дублирования;
- тренировка, из которой вызван экспорт, включается даже за пределами окна;
- явный охват истории и число исключённых тренировок.

Ограничение в 24 тренировки — не тренировочная интерпретация, а ограничение размера транспортного файла. При двух занятиях в неделю это примерно 12 недель сырой истории.

Отдельный полный backup-экспорт может быть добавлен позже, если фактически понадобится.

## 13. Оборудование

Первичная инвентаризация зала может происходить вне Sportzal: пользователь фотографирует оборудование и передаёт фотографии ИИ.

ИИ возвращает стабильные `equipment_id` и описания в `sportzal_program.json`.

В приложении пользователь при желании может привязать локальную фотографию к `equipment_id`. Фото не является обязательным условием выполнения упражнения. Настройка и название фактического оборудования фиксируются с подходом и не меняются задним числом при обновлении каталога. Вес имеет явное значение: показание тренажёра, общий внешний вес, одна гантель, помощь противовеса или собственный вес; приложение не пересчитывает их друг в друга.

## 14. MVP

Обязательный MVP:

- Android APK;
- Kotlin + Jetpack Compose;
- Room;
- импорт `sportzal_program.json`;
- экран «Сегодня»;
- активная тренировка;
- straight и rotation блоки;
- быстрый ввод подхода;
- таймеры по timestamps;
- автосохранение каждого подхода;
- восстановление активной тренировки после закрытия приложения;
- редактирование ошибочно введённого подхода без сброса исходного времени выполнения;
- история тренировок;
- каталог оборудования;
- локальные фото оборудования как необязательная функция;
- завершение тренировки;
- one-tap генерация AI snapshot + Android Share Sheet;
- открытие/импорт совместимого JSON.

## 15. Явно не входит в MVP

- Firebase;
- backend;
- веб-клиент;
- OpenAI API;
- логин;
- многопользовательский режим;
- социальные функции;
- питание;
- калории;
- пульс;
- wearable-интеграции;
- графики прогресса;
- встроенный тренер;
- push-уведомления;
- Android Calendar;
- автоматическое распознавание тренажёров в приложении;
- видеоаналитика техники.

## 16. Контекст тренера и граница MVP

Цель, опыт, ограничения движений и доступное время обсуждаются с ИИ вне приложения. Необязательное `athlete_context` в программе переносит подтверждённые пользователем сведения между экспортами; при отсутствии контекста ИИ уточняет его, приложение не требует анкеты. Заметка к тренировке позволяет один раз сообщить о недосыпе, самочувствии или причине досрочного окончания.

MVP записывает силовые подходы с повторениями. Продолжительность планки, кардио и интервалы по времени не маскируются под повторения и требуют отдельного будущего контракта. Разминка хранится явно как warmup, не увеличивает счётчик рабочих подходов. Число рабочих подходов само по себе не доказывает достаточный стимул; RIR — субъективная оценка пользователя.

## 17. Критерий успеха MVP

MVP успешен, если пользователь может провести реальную тренировку без бумажных заметок и стороннего секундомера, не раздражаясь на ввод данных, а после тренировки одним действием получить файл, достаточный ИИ для анализа и подготовки следующей программы.
